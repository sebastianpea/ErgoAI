# Feature: Evidence-aware ergonomic case intake
Objective: automate only supported observations during new-case intake, preserve manual corrections, and prevent unknown operating context from masquerading as measured data.
Branch: feat/ergoai-evidence-intake
Baseline: current `main` HEAD before feature work; preserve unrelated pre-existing worktree changes.

## Specs
S1. User request: "mira hay algo que se tiene que cambiar al crear un nuevo caso es normal que pida la estacion pero, nececito que por si mismo el sistema defina el tipo de tarea, los parametros consistentes que se tienen que tomar e cuenta por ejemplo en levantamiento que el angulo se defina solo, la altura se puueda calclra pero sea editable, y las condiciones de la actividad esas ni yo se a que hacen referencia asi que mejor que se defina solo, lo mejor es automatizar lo maximo posible pero, que algunos datos en los que pueda fallar sea posible editar de manera manual"
S2. User selected the intake policy: "Solo evidencia observable". Complete only what the photo/system can support; leave unobservable facts unknown and require review before risk calculation. Do not fill in guessed task type, load, frequency/duration, grip, or work height.
S3. Automatically measured posture angles remain confidence-qualified and manually correctable. A work height in centimeters may only be auto-filled when the input includes a reliable scale/calibration; otherwise it remains unknown and editable. Do not infer height from uncalibrated pixels/body proportions.
S4. Explain operational activity factors in plain language and collect them only when observed/confirmed; unknown must not be encoded as REBA activity 0, good grip, zero load, or absent modifiers.
S5. The system must distinguish incomplete/unverified assessment from a confirmed numerical REBA/NOM-036 result. Do not present a default-context preview as final risk, validated assessment, or normative conclusion. Keep manual correction/audit history and existing case data intact.
S6. Preserve the user's original station field, existing file-backed storage, deterministic scoring tables, privacy behavior, and specialist decision workflow. No tracking/video, destructive migration, or fabricated measurement is requested.
S7. User selected "Evaluar modelo adicional": evaluate whether a local classifier can safely suggest task type from static evidence. Do not adopt a model without evidence for supported task classes, local/offline operation, licensing, resource cost, and an explicit confidence/manual-confirmation path. Work height still requires physical calibration evidence.
